# Контракт GInputBridge, используемый виджетом

## Запросы (явные broadcast'ы в `com.salat.gbinder`)

| Action | Extras | Назначение |
| --- | --- | --- |
| `SET_INT_PROPERTY` / `SET_FLOAT_PROPERTY` | `id`, `area`, `value` | записать свойство |
| `GET_INT_PROPERTY` / `GET_FLOAT_PROPERTY` | `id`, `area` | запросить значение |
| `LISTEN_PROPERTY_CHANGES` | `id`, `area` | подписка на изменения `id_area` |
| `GET_FLOAT_SENSOR`, `LISTEN_SENSOR_CHANGES` | `id` | датчики температуры, Fuel Percentage `4211968`, запас хода на топливе `1054720` |
| `CAR_FUNCTION` | `function` | `ME_HOT`, `ME_COLD`, `CLIMATE_MENU`, `SEAT_MEMORY` |

Без `area` мост использует `Integer.MIN_VALUE` (глобальная зона).

## Ответы (неявные broadcast'ы, строковые extras `id`, `area`, `value`)

`PROPERTY_INT_RESULT`, `PROPERTY_INT_CHANGED`, `PROPERTY_FLOAT_RESULT`,
`PROPERTY_FLOAT_CHANGED`, `SENSOR_FLOAT_RESULT`, `SENSOR_FLOAT_CHANGED`.
Неудачное чтение свойства возвращает `-1`.

## Поведение виджета

- подписки GInputBridge хранит в памяти, поэтому служба повторяет `LISTEN_*` и `GET_*` раз в
  60 секунд; значения без ответа дольше 150 секунд считаются устаревшими;
- для зонального свойства дополнительно читается глобальная зона и используется как запасной
  вариант;
- после команды значение показывается оптимистично до 4 секунд, затем — только подтверждённое
  мостом; через 0,8 и 2,5 секунды значение перечитывается;
- мост пересылает `*_CHANGED` только для точной пары `id_area` из подписки; смена режима
  на штатном экране приходит одной пачкой: AUTO (зона 1), скорость, профиль и направление;
- Atlas (проверено 30.09.2026): в AUTO `BLOWING_MODE` зоны 1 = 268894472 (авто), скорость =
  268566794, профиль — один из пресетов; вне AUTO профиль = 255, а направление — ручное
  значение. Зона 4 для направления отдаёт своё, несвязанное значение, глобальная зона — 255;
- люк и шторка панорамной крыши — `WINDOW_POS` (float, процент открытия), шаги как у
  подогревов: люк закрыто → проветривание → 20 → 100, шторка 0 → 20 → 50 → 100. Проветривание —
  `SET_INT_PROPERTY` `SUNROOF_TILT` = 1 в зоне 4 и в глобальной, как у FX11 (он вызывает ECarX
  напрямую, мы — через мост); его состояние читается оттуда же, а для шторки оно считается как
  8 % (столько, по FX11, показывает `WINDOW_POS`). Закрытие сбрасывает `SUNROOF_TILT` в 0 и/или
  ставит положение 0 — что из них открыто. При открытом люке шторка не закрывается: её цикл пропускает
  «закрыто», а открытие люка сначала открывает закрытую шторку до её ближайшей ступени не ниже
  люка; люк при этом трогается через 1,5 с после шторки, иначе машина теряет одну из команд
  (обе ступени выше проветривания — один и тот же `WINDOW_POS`). У `WINDOW_POS` нет запасной
  глобальной зоны: там значение другого стекла, и люк показывал бы положение шторки.
  Неподтверждённое положение не переотправляется: пока стекло едет, оно сообщает промежуточные
  значения, а повтор цели может его остановить. Через 1,5 с после последнего изменения
  положение (как и багажник, и зеркала) перечитывается: серия изменений может закончиться
  промежуточным значением. Остановку между
  ступенями виджет показывает ближайшей пройденной, любое открытие — не меньше первой;
- виджет читает `HVAC_FUNC_AUTO` и показывает неприменимые в текущем режиме кнопки серыми
  (направления в AUTO, пресеты вне AUTO); если прошивка сообщает сохранённый выбор, он
  обводится рамкой;
- в AUTO машина молча игнорирует `FAN_SPEED`, а вне AUTO — профиль; смена режима сразу
  возвращает сохранённые скорость и профиль. Поэтому тап по скорости в AUTO шлёт AUTO=0, а
  тап по пресету вне AUTO — AUTO=1, и само значение уходит через 0,9 с (проверено на Atlas).
- при выключенном климате (`HVAC_FUNC_POWER` = 0) машина сообщает AUTO = 0 и ручное
  направление, а при включении возвращается в прежний режим (со слов пользователя, 15.10.2026).
  Виджет помнит режим, в котором климат выключили, и показывает блок вентилятора в нём; не
  проверено, приходит ли AUTO = 0 до или после `POWER`, поэтому смена AUTO за 2 с до
  выключения не учитывается. Если виджет запущен уже при выключенном климате, режим неизвестен
  и показывается сообщённый машиной.

## Прямой режим (эксперимент)

Вместо моста виджет может обращаться к `com.ecarx.xui.adaptapi` сам, как FX11:
`Car.create(context)`, затем `ICarFunction` (`getFunctionValue`/`setFunctionValue`,
`getCustomizeFunctionValue`/`setCustomizeFunctionValue` для float) и `ISensor`
(`getSensorLatestValue`, `registerListener`). Глобальная зона — вызовы без зоны, как мост
поступает без `area`. `UnsupportedOperationException` считается ответом `-1`, как у моста.
Вотчер (`registerFunctionValueWatcher(id, …)`) регистрируется только после успешного чтения и
заново после сбоя. Значение из вотчера не используется: изменение перечитывает все
отслеживаемые зоны функции, потому что в какой зоне машина сообщает глобальные функции, не
проверено, а вызовы приходят на разных binder-потоках и при быстрой серии путаются по порядку
(шторка после резкого движения оставалась «открытой на 1»). `CAR_FUNCTION`
по-прежнему идёт через мост. На ГУ не проверено ничего из этого раздела.
